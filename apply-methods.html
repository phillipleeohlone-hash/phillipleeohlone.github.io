Four Ways to

Same box-office dataset, four different tools: Series.apply, DataFrame.apply across rows and columns, .map, and skipping apply entirely with vectorized operations.

About This Deck

The Dataset

movies_by_year.csv has one row per year (1980–2015): Year, Total Gross (in $M), Number of Movies released, and that year's #1 Movie. Two numeric columns and one text column is exactly the mix that makes the different flavors of apply worth comparing.

The Four Tools, Side by Side

Series.apply

df[col].apply(fn)
calls fn once per value in one column
fn(value) → value
fn takes a single cell, returns a single result

DataFrame.apply

df.apply(fn, axis=0)
fn runs once per column (fn sees a whole column)
df.apply(fn, axis=1)
fn runs once per row (fn sees a whole row)

.map

df[col].map(fn)
Series-only; fn OR a dict/Series lookup
df[col].map({...})
recode values by lookup, no function needed

Vectorized

df[a] / df[b]
whole-column arithmetic, no apply at all
df[col].str.contains(x)
built-in string ops, run on the whole column
np.where(cond, a, b)
vectorized if/else across a whole column

Applying to a Table
DataFrame.apply hands your function a whole column or a whole row at once — axis decides which.
Concept · Reading axis

axis=0 Goes Down, axis=1 Goes Across

The axis argument names the direction that gets collapsed. axis=0 collapses down each column, so fn receives one column (a Series) at a time. axis=1 collapses across each row, so fn receives one row (a Series) at a time.

axis=0 · fn(column)

One call per column — fn sees every year's value for one field.

axis=1 · fn(row)

One call per row — fn sees every field for one year at once.

2.1 · axis=0, Whole Columns

One Call per Column

  • With axis=0 (the default), fn gets an entire column as a Series and returns one summary value for it.
  • Restrict to the numeric columns first — a function expecting numbers will fail on the text column.

map vs. apply
Both call something on every value of a Series — but only one of them accepts a lookup table.
3.1 · Same Function, Same Result

On a Series, map and apply Often Agree

  • Series.map(fn) and Series.apply(fn) do the same thing when fn is a plain function of one value.
  • The difference only shows up once you reach for what each one can't do — see the next two questions.

3.2 · map's Superpower: a Lookup Table

Recoding Values with a Dictionary

  • map accepts a dict (or another Series) instead of a function — it looks each value up directly.
  • apply has no equivalent: passing a dict to apply is an error, because apply only ever calls something.

3.3 · apply's Superpower: Whole Rows

map Can't See More Than One Column

  • map only exists on a Series — there's no DataFrame.map that works row-by-row like axis=1 apply does.
  • If your function needs values from two or more columns at once (like Question 2.2), apply(..., axis=1) is the only one of the two that can do it.
This won't work
movies["Total Gross"].map(lambda g: g / movies["Number of Movies"])
# map's fn only ever sees one Total Gross value,
# never the matching Number of Movies for that same row

4.2 · Vectorized if/else

np.where Instead of an apply'd if/else

  • np.where(condition, if_true, if_false) checks a whole boolean Series at once and picks a value for every row.
  • It's the vectorized equivalent of an if/else you'd otherwise write inside a function and apply.

Rule of Thumb
If pandas or NumPy already has a vectorized way to say what you mean, use it. Reach for apply when the logic genuinely needs a custom, row-by-row rule — and reach for map only when a Series-only lookup or function is all you need.
