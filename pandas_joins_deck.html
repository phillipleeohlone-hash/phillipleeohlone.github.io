2.2 · Handling Overlapping Columns

Why Column Names Get a Suffix

  • orders and customers both have a column named date, and date is not part of the join key.
  • A DataFrame cannot hold two columns with the exact same name, so merge() renames the colliding ones instead of dropping either.
  • By default the version from the left table gets the suffix _x and the version from the right table gets _y: date becomes date_x and date_y.
  • Only columns that collide outside the join key get a suffix. customer_id stays as one column because it is the key you joined on.
Out[3]:
Index(['order_id', 'customer_id', 'date_x',
       'amount', 'name', 'date_y'],
      dtype='object')
In [4]:
# set your own suffixes instead of _x / _y
pd.merge(orders, customers, on='customer_id',
         suffixes=('_order', '_signup'))
  • To fix the names after the fact instead: merged.rename(columns={'date_x': 'order_date', 'date_y': 'signup_date'})
  • To remove a suffixed column entirely: merged.drop(columns=['date_y'])

Matching Keys
What to do when the two tables don't use the same name for their join column.
3.1 · Different Key Names

on vs. left_on and right_on

In [5]:
accounts = pd.DataFrame({
    'acct_id': [101, 102, 104],
    'plan': ['Premium', 'Basic', 'Premium']
})
accounts
Out[5]:
   acct_id    plan
0      101  Premium
1      102    Basic
2      104  Premium
  • on='col' works when both tables use the same column name for the join key.
  • accounts uses acct_id instead of customer_id. Use left_on for the left table's key column and right_on for the right table's.
  • Both key columns stay in the result — pandas does not know they represent the same thing, only that you told it to match their values.
  • Drop the duplicate afterward with .drop(columns=[...]) if you only need one copy.
In [6]:
pd.merge(orders, accounts,
         left_on='customer_id',
         right_on='acct_id')

Choosing How Rows Match
Control which rows survive the merge when a key doesn't appear in both tables.
4.1 · The how= Parameter

Join Types: inner, left, right, outer

  • how='inner' (the default) keeps only rows whose key appears in both tables. Customer 103 has no matching acct_id, so it is dropped.
  • how='left' keeps every row from the left table, filling in NaN where the right table has no match.
  • how='right' keeps every row from the right table, filling in NaN where the left table has no match.
  • how='outer' keeps every row from both tables, filling in NaN on whichever side is missing.
In [7]:
pd.merge(orders, accounts,
         left_on='customer_id',
         right_on='acct_id',
         how='outer')

Joining on the Index
A second way to combine two tables, when the key is already an index instead of a column.
5.1 · df.join()

Joining on the Index: df.join()

  • .join() combines two DataFrames using their index by default, not a shared column.
  • customers.set_index('customer_id') moves the key out of the columns and into the index.
  • orders.join(customers_idx, on='customer_id') matches each row's customer_id column to the index of customers_idx.
  • .join() defaults to how='left', keeping every row from the calling table. merge() defaults to how='inner'.
  • Overlapping column names are not auto-suffixed here. .join() raises an error unless you supply lsuffix and rsuffix yourself.
In [8]:
customers_idx = customers.set_index('customer_id')

orders.join(customers_idx, on='customer_id',
            lsuffix='_order', rsuffix='_signup')

Pivot Tables
Once two tables are merged, pivot_table() summarizes the result into a grid.
6.1 · pivot_table()

Summarizing a Merge with pivot_table()

In [9]:
orders['category'] = [
    'Electronics', 'Home',
    'Home', 'Home',
    'Home', 'Electronics',
    'Electronics'
]
merged = pd.merge(orders, customers,
                   on='customer_id')
In [10]:
pd.pivot_table(
    merged, values='amount',
    index='name', columns='category',
    aggfunc='sum', fill_value=0
)
  • pivot_table() summarizes a table you already have — often the output of a merge — into a compact grid.
  • index='name' groups rows by customer, columns='category' spreads the category values into their own columns.
  • values='amount', aggfunc='sum' says what to put in each cell and how to combine rows that land in the same spot.
  • fill_value=0 replaces NaN for combinations that never occurred — Ana never bought anything in Electronics.

name

Devon             0.00   42.00

Priya            59.99   15.50
Sofia            30.00    0.00
6.2 · Visualizing pivot_table()

Plotting the Pivot Table

  • A pivot table is just a DataFrame, so any plotting method works directly on it — no reshaping needed.
  • A heatmap is the natural fit for a full grid: color shows magnitude, annot=True prints the exact value in each cell.
  • A bar chart works well for comparing categories within each row — pivot.plot(kind='bar') turns every column into its own bar series.
In [11]:
# heatmap
import seaborn as sns
import matplotlib.pyplot as plt

pivot = pd.pivot_table(
    merged, values='amount',
    index='name', columns='category',
    aggfunc='sum', fill_value=0
)

sns.heatmap(pivot, annot=True,
            fmt='.2f', cmap='Blues')
plt.show()
In [12]:
# grouped bar chart, straight off the pivot table
pivot.plot(kind='bar')
plt.show()

Wrap-Up

Wrap-Up

  • If you don't pass on=, left_on=, or right_on=, pandas joins on every column name the two tables have in common — check that this is what you intended.
  • Use merge() when the key lives in a column on both sides. Use join() when the key is already the index of one side.
  • Check df.columns immediately after every merge or join, before doing anything else with the result.
  • Full parameter list: pandas.pydata.org — DataFrame.merge · DataFrame.join
