Before You Start

Look, Fix, Check

Clean before you make any chart or run any test. A bad row or a number stored as text will quietly break everything after it.

1

Look

Run a few quick checks to find what's wrong. Write down each problem before you fix anything.

2

Fix

Fix one problem per code cell in your notebook. Start each cell with a # comment saying what you fixed and why.

3

Check

Rerun the checks from step 1. Every problem you found should be gone.

Rows That Don't Belong
Summary rows, repeated rows, and rows from outside the group you're studying.
1.1 · Summary Rows

Dropping Summary Rows

  • Some datasets include rows that add up other rows, like Total, All or a whole region. They'd be counted twice in any average.
  • Look at df.tail(15). Summary rows are usually at the bottom, and often have blanks in columns that real rows always fill in.
  • Drop them using that blank column, or by filtering on their names.
  • Add .copy() when you'll change columns afterward. It prevents pandas' SettingWithCopyWarning.
df.tail(3)
     city       state  population
48   Fresno     CA     545,567
49   All West   NaN    78,588,572
50   All U.S.   NaN    331,449,281
In [ ]:
# Drop summary rows: they have no state
df = df.dropna(subset=['state']).copy()
len(df)   # check: 2 fewer rows
1.2 · Duplicates

Dropping Duplicate Rows

  • A row that appears twice counts twice: in means, in group counts, and in a train/test split.
  • df.duplicated() is True for each row that exactly repeats an earlier one, so .sum() counts them.
  • drop_duplicates() keeps the first copy and drops the rest.
  • Check len(df) before and after. The difference should equal the count you found.
In [ ]:
df.duplicated().sum()     # 3
len(df)                   # 120

# Drop 3 repeated rows
df = df.drop_duplicates()
len(df)                   # 117
1.3 · Filtering Rows

Removing Rows Outside Your Study

  • Sometimes a row is real data that doesn't belong in your question, like a city from another country in a study of U.S. cities.
  • value_counts() counts how many times each distinct value appears in a column, from most to least common. On a category column, it's the fastest way to notice a value that shouldn't be there.
  • Keep the rows you want with a condition inside df[ ].
  • Explain in your comment why the row doesn't belong. Dropping data needs a reason.
In [ ]:
df['country'].value_counts()
# USA      116
# Canada     1

# Keep only U.S. cities: our question is about the U.S.
df = df[df['country'] == 'USA'].copy()

Numbers Stored as Text
Commas, dollar signs, percent signs and missing-value symbols turn a number column into text.
2.1 · Extra Characters

Removing Commas, $ and %

  • df.info() lists the column as object, not int64 or float64. You can't take its mean or plot it.
  • Remove each extra character with .str.replace, then convert with .astype.
  • Chain several replaces when a value has more than one, like $ and commas.
stored asshould be
"545,567"→545567
"$72,400"→72400
"18.5%"→18.5
In [ ]:
# population had commas, so it was text
df['population'] = (df['population']
                    .str.replace(',', '')
                    .astype(int))

# rent had $ and commas
df['rent'] = (df['rent']
              .str.replace('$', '')
              .str.replace(',', '')
              .astype(int))

# poverty_pct had % signs
df['poverty_pct'] = (df['poverty_pct']
                     .str.replace('%', '')
                     .astype(float))
2.2 · Missing-Value Symbols

Turning Symbols Into Missing Values

  • Data sources mark missing values in different ways: .., *, -, N/A. Read the source's notes to see what a symbol means.
  • One symbol anywhere in the column makes the whole column text.
  • pd.to_numeric(..., errors='coerce') converts everything it can and turns the rest into NaN, pandas' missing value.
  • Afterward, check df['col'].isna().sum() to see how many values are missing. Then decide whether to drop those rows or leave the column out, and say why.
In [ ]:
df['test_score'].unique()[:4]
# '71.2', '68.0', '*', '74.5'

# * means hidden (too few students): make it NaN
df['test_score'] = pd.to_numeric(df['test_score'],
                                 errors='coerce')
df['test_score'].isna().sum()

IDs, Categories and Names
Codes that lost their zeros, categories that are spelled more than one way, and column names that are hard to type.
3.1 · Leading Zeros

Restoring Leading Zeros

  • Many ID codes have a fixed number of digits. A U.S. ZIP code is always 5 digits: Boston's is 02134.
  • When a code is read as a number, its leading zero disappears: 02134 becomes 2134.
  • This matters when you merge two files: 2134 and "02134" won't match.
  • IDs are labels, not quantities, so store them as text. Check the dataset's README for how many digits each code should have.
stored asshould be
2134→"02134"
94539→"94539"
In [ ]:
# zip lost its leading zeros when read as a number
df['zip'] = df['zip'].astype(str).str.zfill(5)
3.2 · Inconsistent Categories

Making Categories Match

  • To Python, "Urban", "urban" and "Urban " (with a space) are three different groups.
  • Left alone, one group is split into pieces and every group comparison is wrong.
  • .str.strip() removes extra spaces. .str.lower() or .str.upper() makes capitalization match.
  • Rerun value_counts() afterward. You should see one row per real group.
df['area'].value_counts()
Urban      61
Rural      44
urban       6
Urban       4   # trailing space
RURAL       2
In [ ]:
# area had extra spaces and mixed capitals
df['area'] = df['area'].str.strip().str.lower()
df['area'].value_counts()   # urban 71, rural 46
3.3 · Column Names

Renaming Columns

  • Some files keep the original source's column names, like "Median Rent ($)" or "Days with Data".
  • Names with spaces, capitals and symbols are easy to mistype. Short, lowercase names with underscores make the rest of your code easier to read.
  • rename takes a dictionary: old name → new name. You only need to list the columns you're changing.
In [ ]:
# Shorter, consistent column names
df = df.rename(columns={
    'City Name': 'city',
    'Median Rent ($)': 'rent',
    'Days with Data': 'days_measured',
})
df.columns

Columns You Compute
Turning counts into rates and percents, and measuring change over time.
4.1 · Rates

Turning Counts Into Rates

  • A big city has more of almost everything (crimes, hospitals, car crashes) mostly because it has more people.
  • To compare places of different sizes, divide by size: for example, per 100,000 people.
  • The same goes for any count measured over different amounts: if places were measured on different numbers of days, compare the percent of days, not the count.
  • If your dataset only has counts, ask whether your question needs a rate.
In [ ]:
# Crimes per 100,000 people, so cities of
# different sizes can be compared
df['crimes_per_100k'] = (
    100000 * df['crimes'] / df['population']
).round(1)

# Percent of measured days that were rainy
df['rainy_pct'] = (
    100 * df['rainy_days'] / df['days_measured']
).round(1)
4.2 · Change

Measuring Change Between Years

  • When a dataset gives the same measurement for two years, the question is often how much it changed.
  • Subtract the earlier year from the later one. A negative value means it went down.
  • When both columns are percents, the change is in percentage points: going from 40% to 35% is a change of −5 points.
In [ ]:
# Change in graduation rate, 2015 to 2020
df['grad_change_pts'] = (
    df['grad_pct_2020'] - df['grad_pct_2015']
).round(1)

df.sort_values('grad_change_pts').head()

Checking and Saving
Confirming the fixes worked, saving the cleaned dataset, and organizing the notebook you submit.
5.1 · Recheck

Rerunning the Checks

  • Run the same checks you used to find the problems. Every number column should now be int64 or float64.
  • Duplicates should be 0, and each category should appear once in value_counts().
  • Any missing values left are real gaps in the data. Say in your notebook how you handled them.
In [ ]:
df.info()                    # types fixed?
df.duplicated().sum()        # 0?
df['area'].value_counts()    # one per group?
df.isna().sum()              # what's still missing?
df.describe()                # any odd values?
5.2 · Saving

Saving the Cleaned Dataset

  • to_csv writes your cleaned table to a new CSV file. This is the file you submit.
  • Use index=False. Otherwise pandas adds an extra unnamed column of row numbers.
  • Save to a new file name. Never overwrite the original. Your notebook should always start from the raw file.
  • Read the saved file back in and run info() once more to confirm it saved correctly. ID columns with leading zeros need dtype={'zip': str} when you read them back.
In [ ]:
# Save the cleaned data to a new file
df.to_csv('cities_clean.csv', index=False)

# Check that it saved correctly
check = pd.read_csv('cities_clean.csv',
                    dtype={'zip': str})
check.info()
5.3 · Notebook

Organizing Your Cleaning Notebook

  • Top: a markdown cell naming your dataset and listing every problem you found, in a short numbered list.
  • Load: read the original file and run your checks, so the problems are visible.
  • Fix: one problem per code cell, each starting with a # comment.
  • Check and save: rerun the checks, then save the cleaned CSV.
  • Before you submit, choose Kernel → Restart & Run All. The notebook should run top to bottom with no errors and produce the same cleaned file.
Markdown cell
## Cleaning: cities.csv

Problems found:
1. 2 summary rows at the bottom
2. 3 duplicate rows
3. population and rent stored as text
4. "area" spelled several ways

Saved as cities_clean.csv
Wrap-Up

Before You Submit

  • The cleaned dataset: a new CSV file, saved with index=False.
  • The cleaning notebook: a list of the problems you found, one fix per code cell with a comment, and your checks before and after.
  • The notebook runs from top to bottom with Restart & Run All, starting from the original file.
  • Read your dataset's section in the README first. It describes every column, which helps you tell what looks wrong.
