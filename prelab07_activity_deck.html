How a Permutation Test Works
The idea and the reason it is valid, before any code.
How It Works · The Question

What a Permutation Test Asks

A made-up example: hours of sleep for 3 cats and 3 dogs. The cats' average is 15 hours and the dogs' average is 10, a gap of 5. Is that gap real, or could luck produce it?

  • Null hypothesis: species makes no difference to sleep. Any gap in our sample is due to chance.
  • Alternative hypothesis: cats sleep more than dogs, on average.
  • Test statistic: average cat hours minus average dog hours. Observed value: 5.
  • The key question: if the null were true, how often would chance alone give a gap this big?

How It Works · The Reason

Why Shuffling Labels Works

If the null is true, a pet's species has nothing to do with how long it sleeps. Then the labels “cat” and “dog” are just tags, and any other way of handing out the tags was equally likely to happen.

  • Each shuffle is a “what if the tags had landed differently?” world. It shows a gap that luck of labeling alone can produce.
How It Works · The Recipe

The Five Moves

  1. 1
    Compute the observed statistic from the real labels (the gap of 5).
  2. 2
    Shuffle the labels at random. Keep the same number of cats and dogs.
  3. 3
    Compute the statistic for the shuffled table. This is one simulated gap.
  4. 4
    Repeat steps 2 and 3 thousands of times to collect many simulated gaps.
  5. 5
    Compare. The p-value is the fraction of simulated gaps at least as extreme as the real one.

Why keep the group sizes? The real study had 3 cats and 3 dogs, so every simulated world must too. Shuffling does this automatically: it reorders the labels without adding or dropping any.

How It Works · Reading the Result

Where Does the Real Result Land?

Each bar shows how often a simulated gap fell in that range. The red dot is the real gap.

Dot far out in the tail
Chance rarely makes a gap this big. The p-value is small, so the data are hard to explain with the null.
Dot near the middle
Chance produces gaps like this all the time. The p-value is large, so the data are consistent with the null.
How It Works · Interpreting

What a p-Value Means

It tells you
  • How surprising your result would be if the null were true.
  • A small p-value is evidence against the null. Many courses use a 5% cutoff.
  • A large p-value means the result is consistent with chance. It does not prove the null.
It does not tell you
  • The probability that your conclusion is wrong, or that the null is true.
  • Why the groups differ. Cause needs random assignment, not just a small p-value.
  • Anything about people outside the data's population.

Remember: a gap in the sample does not automatically mean a gap in the population. The permutation test is how we check whether chance could explain it.

Steps 2, 5, 6 · Using the Result

Looking Up a Group's Value

  • The result is a Series whose row labels are the group names.
  • Look up a group by its name, not by a position number: means['cat'].
  • Names are case sensitive and must match the table exactly.
  • Because each lookup is a plain number, you can do arithmetic on them, like a difference of two groups.
In [2]:
means = pets.groupby('pet')['hours'].mean()
means['cat']
# 15.0

means['cat'] - means['dog']
# 5.0
Troubleshooting

Common groupby Mistakes

  • Leaving out the column. pets.groupby('pet').mean() averages every number column, not just the one you wanted.
  • Misspelling a group name. means['Cat'] raises a KeyError because the label is 'cat'.
  • Expecting the table to change. groupby never edits pets. It returns a new result.
  • Forgetting the brackets and quotes. Column and group names are strings: ['hours'], not [hours].
In [3]:
pets.groupby('pet').mean()
# every numeric column is averaged

means['Cat']
# KeyError: 'Cat'

Steps 3 and 5 · Random Order

np.random.permutation

  • It returns a shuffled copy of an array.
  • The original is not changed.
  • Every item appears exactly as many times as before. Only the order changes.
  • Run it again and you get a different order.

letters = np.array(['A', 'A', 'B', 'B'])
np.random.permutation(letters)
# e.g. ['B' 'A' 'A' 'B']

letters

Copying a Table and Replacing a Column

  • pets.copy() makes a separate table, so changing the copy leaves the original safe.
  • shuffled['pet'].values hands you that column as an array, ready to shuffle.
  • Assigning to shuffled['pet'] replaces the whole column with the shuffled version.
  • The hours column is never touched, so each number stays in its row.

Step 4 · Counting Arrangements

Keeping Only Different Arrangements

  • A set stores each item once. Adding something already inside does nothing.
  • seen.add(x) puts x in the set. len(seen) counts what is inside.
  • A set cannot hold an array or a list. Convert first with tuple(...).
  • So: shuffle many times, add each result as a tuple, and the set keeps only the different arrangements.
  • Not guaranteed: random shuffling is not a sure way to find every arrangement. With few possibilities and many shuffles it works almost every time, but a rare arrangement can be missed.
In [6]:
seen = set()
seen.add(('A', 'B'))
seen.add(('B', 'A'))
seen.add(('A', 'B'))   # duplicate
len(seen)
# 2

Step 4 · Slicing

Slicing Shortcuts

  • Leave out start to begin at the front: arr[:3].
  • Leave out stop to go to the end: arr[3:].
  • The pieces arr[:3] and arr[3:] together are the whole array, with nothing repeated.
  • A negative number counts from the end: arr[-2:] is the last two.

Step 4 · Reading a Given Cell

Listing Every Arrangement

In Step 4 a cell is given that lists all possible arrangements on purpose, so nothing is left to chance (unlike random shuffling). You do not write it, but you should be able to read it. It uses two ideas.

  • combinations(range(4), 2) lists every way to choose 2 of 4 positions.
  • A mask is an array of True/False the same length as your data. arr[mask] keeps the True positions. arr[~mask] keeps the rest (~ flips True and False).

Step 6 · Functions

A Function That Returns a Number

  • A function packages steps so you can run them again with one call.
  • return sends a value back. Without it, the call gives you nothing to keep.
  • This function takes no inputs, but still needs the parentheses: one_roll().
  • Because the steps include randomness, each call can give a different answer.
In [9]:
def one_roll():
    return np.random.randint(1, 7)

one_roll()   # 4
one_roll()   # 1

Step 7 · Repetition

Repeating with a List Comprehension

  • [one_roll() for _ in range(5)] calls the function 5 times and collects the results in a list.
  • _ is just a throwaway name. We need the repeat, not the counter.
  • Wrap it in np.array(...) so you can compare and count the values later.
  • It is a shorter version of a for loop that appends to a list.
In [10]:
rolls = np.array([one_roll() for _ in range(5)])

Steps 4 and 8 · Counting

Counting for a p-Value

  • Comparing an array to a number gives an array of True/False, one per value.
  • np.count_nonzero(...) counts the True values.
  • Divide by len(...) to turn the count into a fraction.
  • That fraction is the p-value: how often chance alone gave a result at least as extreme as the real one.
In [11]:
sims = np.array([2, -1, 4, 0, 3])
sims >= 3
# [False False True False True]

np.count_nonzero(sims >= 3)
# 2

np.count_nonzero(sims >= 3) / len(sims)
# 0.4

Choosing the Direction

Which shuffled values count as “at least as extreme” depends on what the alternative hypothesis says. Here obs is the real result and sims are the shuffled results.

Different (either way)as far from 0 as the real result  →  np.abs(sims) >= abs(obs)
